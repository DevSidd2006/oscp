# Actual exFAT image records and allocated-file export

The exFAT module reads actual on-image structures from a selected regular raw image. It never substitutes demo record maps. `inventoryExfatRoot` validates main boot-region checksum and extended boot signatures, sector/cluster geometry, clean volume flags, the active FAT root chain, file entry-set checksums, immediate stream extensions and UTF-16 names. It records stream lengths, first cluster, contiguous allocation flags and actual record offsets. Inactive entries are observed only as unused slots; their names/chains are not reconstructed or claimed as deleted files.

The parser is bounded to 128 root clusters, 4 MiB of directory entries, 1024 file sets and 8 MiB of metadata reads. Unknown critical extensions, bad chains, checksum mismatches, dirty/media-failure flags, unsupported entry sets and missing bitmap/up-case metadata produce invalid/partial results. Such results cannot authorize export. Directory recursion and whole-filesystem consistency checks are not implemented. Backup boot-region verification is not performed.

`extractExfatCandidate` accepts only allocated regular root files with fully initialized data (`ValidDataLength == DataLength`). It follows and bounds the active allocation bitmap and up-case table, verifies their allocation/chain geometry, checks the up-case checksum, decodes compressed/uncompressed Unicode mappings and verifies the filename hash. It verifies candidate allocation bits, FAT chains or `NoFatChain` contiguous extents, expected chain length and lack of overlap with root/bitmap/up-case metadata. Limits are 64 MiB per file and 16384 file clusters. Two-FAT/TexFAT export, partially initialized streams, deleted entries, directories and NTFS extraction are explicitly unsupported. It exports only logical initialized bytes, excluding final-cluster slack.

`createExfatExtractionService` retains the existing selected-image identity, opens the source read-only and verifies held/visible identity around bounded reads. Native output selection and trusted helper resolution must establish independent physical source/destination identities, known capacity and unchanged topology. New output and metadata sidecars use exclusive creation. Cancellation/failure retains partial output. Successful completion requires output rereading with matching SHA-256 plus metadata and audit persistence. This is allocated-file export from a stored image, not live acquisition or deleted-file recovery.

`createImageRecoveryProvider` implements the generic provider port for actual stored-image FAT32/exFAT analysis and allocated export. Source/record IDs are opaque; source paths remain private. NTFS/unknown record analysis and physical acquisition return unsupported/unavailable rather than fabricated records. `selectRecoveryWorkflowProvider` can accept this explicitly configured image adapter; it rejects physical-execution adapters until a separately reviewed factory change. Demo remains a separate explicit selection, with no production fallback to synthetic content.

The production image adapter is wired into trusted main-process IPC and the validated preload API: `analyzeImageRecords(imageId)`, `startImageFileExport(imageId, recordId)`, `getImageFileExport()` and `cancelImageFileExport(requestId)`. The renderer's combined FAT32/exFAT panel displays actual records, blocks deleted/directory/uncertain candidates and requires an explicit allocated-export acknowledgement before opening the native destination picker. Source and output paths are never accepted as renderer arguments. The workflow returns a request-bound running/finished job, validates source/record/result correlation and refuses demo, NTFS or physical-acquisition claims. Shutdown cancels and drains the provider before the selected image is closed. The legacy FAT32-only endpoints remain compatible.

Format behavior follows [Microsoft's exFAT specification](https://learn.microsoft.com/en-us/windows/win32/fileio/exfat-specification), including boot/entry-set checksums, active FAT/bitmap association, `NoFatChain`, up-case table compression and filename hashes. In particular, bytes beyond `ValidDataLength` are undefined and must read as zero; this implementation refuses those streams instead of exposing stale storage bytes.

Tests construct real encoded boot regions, FATs, allocation bitmaps, compressed up-case tables and entry sets in disposable regular raw images. They exercise fragmented and contiguous output, corrupt checksums/Unicode/name hashes, free/cyclic/short/long/metadata-overlapping allocation, mutation, same-device output refusal, cancellation, hashes and audit uncertainty. These are actual parser tests against image bytes, not validation against a live VM, hardware device, or every native formatter. VHD/VHDX/E01 container decoding and native-format interoperability validation remain separate work. No custom NTFS parser exists in this module.
