# Task 2 — Windows Storage and Forensic Helper Architecture

## Objective

Design and implement the read-only Windows helper boundary for safe device enumeration and forensic acquisition.

## Scope

- Define the C#/.NET helper process and authenticated local transport.
- Use Windows Storage Management APIs for disks, partitions, volumes, and physical devices.
- Normalize device identity, capacity, media type, serial number, system-disk status, and access mode.
- Support device disappearance and identity changes without substituting another device.
- Enforce read-only access for acquisition and enumeration.

## Deliverables

- Helper project structure under `src/Oscp.Helper/`.
- Versioned request/response contracts.
- Electron main-process helper client.
- Fake storage provider for Linux development and tests.
- Unit tests for framing, request IDs, timeouts, response correlation, and device identity.

## Acceptance criteria

- The renderer cannot access raw device paths, filesystem APIs, or shell commands.
- Unknown commands, malformed messages, duplicate responses, and unsolicited responses fail safely.
- Enumeration returns normalized devices and partitions.
- A changed or missing target returns an explicit error.
- Tests run without requiring a Windows machine by using the fake provider.

## Dependencies

- Shared contracts used by the preload bridge.
- Sanitization fields required by Task 1.
