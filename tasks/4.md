# Task 4 — OSCP Implementation Plan, Audit, and Verification

## Objective

Convert the research findings into a staged implementation plan and close the current repository gaps.

## Scope

- Replace demo-only assumptions with explicit demo mode and real-device mode.
- Define shared TypeScript contracts for devices, jobs, audit events, errors, and verification.
- Add immutable or tamper-evident JSON Lines audit storage with chained SHA-256 digests.
- Add unit and integration tests for the preload bridge, helper client, device identity, and audit chain.
- Add reproducible dependency management and CI build/test commands.
- Keep destructive operations disabled until the safety gates are implemented and tested.

## Deliverables

- Updated `src/shared/types.ts` contracts.
- Audit/event service and tests.
- Explicit demo-data indicator in the UI.
- Error and capability states in the renderer.
- Pinned dependency versions and committed lockfile.
- Test coverage for safety-critical state transitions.
- Updated README with completed, in-progress, and unavailable features.

## Acceptance criteria

- `npm ci`, `npm run build`, and `npm test` work from a clean checkout.
- The UI never presents demo devices as real connected devices.
- Audit records can detect modification, deletion, reordering, and broken sequence continuity.
- No destructive operation is exposed through the preload API before the corresponding helper and verification controls exist.
- Documentation accurately reflects the implementation status.

## Dependencies

- Standards model from Task 1.
- Helper contracts from Task 2.
- Recovery workflow from Task 3.
